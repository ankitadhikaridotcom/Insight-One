# Developer Workflow & Coding Standards

This guide explains how frontend and backend developers interact with Supabase and maintain high code quality across the **Insight One** repository.

---

## 1. Golden Rule: No Inline Queries in TypeScript

> [!CAUTION]
> **NEVER write direct SQL queries or table mutations in `.ts` or `.tsx` files.**
> 
> ❌ **Prohibited**:
> ```typescript
> // VIOLATION: Never query or mutate tables directly
> const { data } = await supabase.from('projects').select('*');
> await supabase.from('clients').insert({ name: 'Acme Corp' });
> ```
> 
> ✅ **Mandatory Standard**:
> ```typescript
> // CORRECT: Every operation executes a security definer database function
> const response = await callRpc<Project[]>('fn_projects_list', { p_client_id: 12 });
> if (response.is_success) {
>   console.log(response.data);
> }
> ```

## 2. Implementing New Database Tables

When creating a new business entity table, follow this template to ensure it meets the 11-column multi-tenancy rule:

```sql
CREATE TABLE public.feature_items (
    -- 1. Standard Identity Primary Key
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,

    -- 2. Domain Columns
    code TEXT NOT NULL,
    title TEXT NOT NULL,
    description TEXT NULL,

    -- 3. Mandatory Multi-Tenancy & Audit Columns
    data JSONB NULL,
    metadata JSONB NULL,
    access_control JSONB NULL,
    tenant_id INTEGER NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_by INTEGER NOT NULL REFERENCES public.profiles(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_by INTEGER NULL REFERENCES public.profiles(id),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- Enable Row Level Security
ALTER TABLE public.feature_items ENABLE ROW LEVEL SECURITY;
```

## 3. Writing RPC Database Functions

All functions must follow the standard security pattern:

```sql
CREATE OR REPLACE FUNCTION public.fn_feature_items_list(
    p_search TEXT DEFAULT NULL
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, pg_temp
AS $$
DECLARE
    v_ctx JSONB;
    v_tenant_id INTEGER;
    v_items JSONB;
BEGIN
    -- 1. Authorize caller via context validator
    v_ctx := public.fn_get_request_context('fn_feature_items_list');
    IF NOT (v_ctx->>'is_authorized')::BOOLEAN THEN
        RETURN public.fn_response_error(
            'fn_feature_items_list',
            'UNAUTHORIZED',
            v_ctx->>'error_message',
            403,
            NULL,
            NULL,
            v_ctx
        );
    END IF;

    -- 2. Extract tenant ID strictly from authenticated context
    v_tenant_id := (v_ctx->>'tenant_id')::INTEGER;

    -- 3. Query tenant-scoped data
    SELECT jsonb_agg(
        jsonb_build_object(
            'id', f.id,
            'code', f.code,
            'title', f.title,
            'data', f.data,
            'created_at', f.created_at
        ) ORDER BY f.id DESC
    )
    INTO v_items
    FROM public.feature_items f
    WHERE f.tenant_id = v_tenant_id
      AND f.is_active = true
      AND (p_search IS NULL OR f.title ILIKE '%' || p_search || '%');

    -- 4. Return standard JSONB success envelope
    RETURN public.fn_response_success(COALESCE(v_items, '[]'::jsonb), NULL, 'Items retrieved');

EXCEPTION WHEN OTHERS THEN
    -- 5. Catch technical exceptions, log to error_log, and return sanitized message
    RETURN public.fn_response_error(
        'fn_feature_items_list',
        SQLSTATE,
        'Unable to retrieve items at this time',
        500,
        SQLERRM,
        NULL,
        v_ctx
    );
END;
$$;
```

## 4. Consuming RPC Functions in the Frontend

In `src/services/dataService.ts`, expose typed convenience methods wrapping `callRpc`:

```typescript
export class DataService {
  static async getFeatureItems(search?: string): Promise<FeatureItem[]> {
    const res = await callRpc<FeatureItem[]>("fn_feature_items_list", {
      p_search: search || null,
    });
    if (!res.is_success) {
      throw new Error(res.message);
    }
    return res.data || [];
  }
}
```

## 5. UI Component Guidelines

1. **Header Actions**:
   - Always place primary actions in `AppShell`'s `actions` prop.
   - Example:
     ```tsx
     <AppShell
       title="Projects"
       subtitle="Manage client pipelines and delivery milestones"
       actions={
         <button onClick={() => setIsCreateOpen(true)} className="...">
           + New Project
         </button>
       }
     >
       {/* Kanban board or table */}
     </AppShell>
     ```

2. **Modals & Dialogs**:
   - Always use the `<Modal>` component with `maxWidth="3xl"` or larger.
   - Place primary form buttons in the `footer` prop.
   - Central form area automatically scrolls if viewport height is exceeded.

3. **Dropdowns**:
   - Use `<SearchableSelect>` for every single-select or multi-select form field.
   - Provide clean labels and descriptive sublabels.
