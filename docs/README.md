## 🏛️ Core Principles & Inviolable Rules

1. **Strict Multi-Tenancy**:
   - Every tenant can manage multiple agencies.
   - Every agency can manage multiple clients, with each client having multiple social profiles.
   - Every business table **must** include the standardized multi-tenancy columns (`id INTEGER GENERATED BY DEFAULT AS IDENTITY`, `code TEXT`, `data JSONB`, `metadata JSONB`, `access_control JSONB`, `tenant_id INTEGER`, `is_active BOOLEAN`, `created_by INTEGER REFERENCES profiles(id)`, `created_at`, `updated_by INTEGER REFERENCES profiles(id)`, `updated_at`).

2. **Security Definer RPC Protocol**:
   - **Zero inline SQL queries or direct table mutations in `.ts` files**.
   - Every operation must be executed via PostgreSQL `SECURITY DEFINER` functions with search_path protection.
   - All function parameters must start with `p_`.
   - Every function validates caller permissions using `fn_get_request_context(p_function_name)`.
   - All functions return a standardized JSONB envelope via `fn_response_success` or `fn_response_error`.
   - Errors are sanitized for users and logged into the `public.error_log` table.

3. **User Roles**:
   - The platform defines 5 standard roles:
     - **Role Host**: Platform Super Administrator.
     - **Tenant Admin**: Organization/Tenant Owner and Administrator.
     - **content creator**: Content and deliverable producer.
     - **content approver**: Quality assurance, editor, and sign-off manager.
     - **Viewer**: Read-only stakeholder or client observer.

4. **Frontend UX Standards**:
   - **Public Landing Page First**: Landing at `/`, workspace console at `/dashboard`.
   - **Sidebar Profile Card**: Moved to the bottom-left of the sidebar with a popup context menu (View Profile, Workspace Settings, Sign Out).
   - **No Duplicate Links**: Settings and Logout are removed from standard sidebar navigation items.
   - **Fixed Page Header**: All primary page actions are placed in the top-right corner of a sticky/frozen header bar.
   - **Kanban Board Pipelines**: Projects and Content workflows are presented as Kanban boards.
   - **Large Modals with Fixed Actions**: Modals use large sizes (`3xl` to `5xl`) with fixed header, fixed footer action buttons, and scrollable content.
   - **Standard Searchable Dropdown**: The custom `SearchableSelect` component must be used across all forms in place of standard native dropdowns.
   - **Unified Login**: A single, clean login form without separate tabs; user roles and tenant routing are resolved automatically from backend profile metadata.

## 📁 Supabase Folder Structure

All database scripts, functions, migrations, and edge functions are located in the [**`supabase/`**](file:///d:/learningapp/supabase) directory:

```
supabase/
├── README.md                          # Guide for executing migrations and scripts
├── full_schema.sql                    # Unified, single-file executable master script
├── schema/
│   ├── 01_core_multitenancy.sql       # Tenants, agencies, profiles, roles, scopes, error_log
│   └── 02_business_tables.sql         # Standardized business tables with multi-tenancy columns
├── functions/
│   ├── 01_common_helpers.sql          # fn_response_success, fn_response_error, fn_get_request_context
│   ├── 02_auth_and_navigation.sql     # fn_user_me, fn_navigation_menu, fn_tenant_context
│   └── 03_business_rpc.sql            # Secure CRUD functions for all modules
├── seeds/
│   └── 01_initial_seed.sql            # Default tenant, roles, scopes, menu mappings, profiles
├── policies/
│   └── 01_rls_and_permissions.sql     # Row Level Security and GRANT policies
└── edge_functions/
    ├── README.md                      # Edge function guidelines and deployment steps
    └── analytics-aggregator/index.ts  # Reference Deno TypeScript edge function
```
